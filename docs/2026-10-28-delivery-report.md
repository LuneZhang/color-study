## 5. 与上一版的取舍

静态托管不启动服务器，因此上一版的 SQLite、钥匙串、备份恢复、在线教程录入、素材管理后台和浏览器 RAW 统计不在当前界面中。原 `packages/server` 代码保留为原型，不参与构建。当前替代方案：

- 教程与知识卡随仓库数据发布；
- 订阅由 GitHub Actions 每日刷新；
- 收藏、笔记、状态、参考作品存 `localStorage`，可导出/导入 JSON；
- AI 由浏览器直连用户配置的服务商，Key 存浏览器并在设置页说明风险。

## 6. 仍需用户确认

1. 真实 AI 服务商是否允许浏览器直连（CORS）。不允许时需要自建代理并填入代理地址。
2. 是否接受 Hash 路由的 `#/` 分享链接。
3. 是否将订阅源改成自己的名单；当前在 `scripts/fetch-feeds.mjs`。
4. 是否要重新引入素材管理与本地备份；那会需要非 GitHub Pages 的服务器或额外的本地模式。
5. GitHub 仓库名称与 Pages 设置；工作流已适配子路径，无需修改 base。
